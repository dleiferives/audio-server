audio-server API

OpenAI-compatible TTS/STT, queues, streaming, provider discovery, and forced alignment.

How requests flow

client → audio-server → validation/routing → provider queue or STT dispatch → local process / managed CUDA sidecar

TTS requests can block for a result, stream bytes, or return an asynchronous job. GPU providers share one exclusive lifecycle group: the selected sidecar starts on demand and the previous model is stopped to release VRAM. STT uploads are automatically normalized to each provider's required audio format. Provider capabilities and voices are discoverable at runtime.

Use Authorization: Bearer … or X-API-Key: … when authentication is configured. Health and these documentation endpoints are public. See the OpenAPI 3.1 JSON and the repository's docs/api.md for the conceptual guide.
